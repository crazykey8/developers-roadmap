Конечно! Вот подборка **вопросов и ответов по Git**, которые могут пригодиться для собеседования, экзамена или просто для самопроверки:

---

### 🧠 **Основы Git**

**Вопрос 1:** Что такое Git?
**Ответ:**
Git — это распределённая система контроля версий, позволяющая отслеживать изменения в файлах и координировать работу над проектами среди нескольких разработчиков.

---

**Вопрос 2:** В чем разница между `git clone`, `git fetch` и `git pull`?
**Ответ:**

- `git clone` — копирует удалённый репозиторий в новый локальный.
- `git fetch` — загружает изменения с удалённого репозитория, но не сливает их.
- `git pull` — делает `fetch` + `merge` (автоматически применяет изменения в текущую ветку).

---

### 🔄 **Работа с ветками**

**Вопрос 3:** Как создать и переключиться на новую ветку?
**Ответ:**

```bash
git checkout -b new-branch-name
```

---

**Вопрос 4:** Как слить изменения из одной ветки в другую?
**Ответ:**

```bash
git checkout main
git merge feature-branch
```

---

### 💾 **История и коммиты**

**Вопрос 5:** Как отменить последний коммит, но оставить изменения в рабочем дереве?
**Ответ:**

```bash
git reset --soft HEAD~1
```

---

**Вопрос 6:** Как просмотреть историю коммитов?
**Ответ:**

```bash
git log
```

---

### ⚠️ **Ошибки и откат**

**Вопрос 7:** Как отменить изменения в файле, вернув его к последнему коммиту?
**Ответ:**

```bash
git checkout -- filename
```

---

**Вопрос 8:** Что делать, если нужно отменить `git add`?
**Ответ:**

```bash
git reset HEAD filename
```

---

### 🌐 **Удалённые репозитории**

**Вопрос 9:** Как добавить удалённый репозиторий?
**Ответ:**

```bash
git remote add origin https://github.com/user/repo.git
```

---

**Вопрос 10:** Как отправить изменения на удалённый репозиторий?
**Ответ:**

```bash
git push origin branch-name
```

---

### 🔄 **Rebase**

**Вопрос 11:** Чем отличается `git rebase` от `git merge`?
**Ответ:**

- `merge` объединяет ветки, создавая новый коммит.
- `rebase` "переписывает" историю, перенося коммиты одной ветки поверх другой.
  Используется для чистой линейной истории.

---

**Вопрос 12:** Как использовать `rebase` для обновления фиче-ветки?
**Ответ:**

```bash
git checkout feature
git rebase main
```

---

### 💼 **Stash (временное сохранение изменений)**

**Вопрос 13:** Как временно сохранить изменения, не делая коммит?
**Ответ:**

```bash
git stash
```

---

**Вопрос 14:** Как вернуть изменения из `stash`?
**Ответ:**

```bash
git stash pop
```

---

### 🎯 **Cherry-pick**

**Вопрос 15:** Что делает `git cherry-pick`?
**Ответ:**
`git cherry-pick <hash>` применяет конкретный коммит из другой ветки к текущей ветке.

---

**Пример:**

```bash
git cherry-pick a1b2c3d4
```

---

### 🕵️ **Bisect (поиск багов)**

**Вопрос 16:** Как работает `git bisect`?
**Ответ:**
`git bisect` помогает найти коммит, в котором впервые появился баг, используя бинарный поиск между рабочим и нерабочим состоянием.

---

**Пример:**

```bash
git bisect start
git bisect bad        # текущий коммит содержит баг
git bisect good abc123  # коммит abc123 был без бага
```

Далее Git будет предлагать проверять коммиты — вы отмечаете их как `good` или `bad`, пока не найдется виновник.

---

### 🧹 **Очистка, восстановление, удаление**

**Вопрос 17:** Как удалить локальную ветку?
**Ответ:**

```bash
git branch -d branch-name
```

---

**Вопрос 18:** Как удалить ветку на удалённом репозитории?
**Ответ:**

```bash
git push origin --delete branch-name
```

---

**Вопрос 19:** Как очистить untracked файлы (неиндексированные)?
**Ответ:**

```bash
git clean -f
```

---

**Вопрос 20:** Как отменить изменения во всех файлах и вернуться к последнему коммиту?
**Ответ:**

```bash
git reset --hard HEAD
```
